# V0.1 measurement

These measurements use the frozen `d5f61cb` fixture interface and verifier. Current fixture commands require a host build receipt. See the [README](../README.md) for the current interface.

The November 17, 2026 trials used AgentDock revision `560886e07d652410349f8b2ae8e479d89593d623`. Four clean replays passed independent artifact verification. The fresh Codex sessions measured recipe preparation or CLI/Skill generation, with packaging and verification outside the Codex timer. The initial observations cover one pair per fixture and phase. The [matched follow-up](#matched-follow-up) records the full request-to-verdict and common-boundary replay measurements.

## Clean recipe replay

E2E used the same frozen Dockerfile, application snapshot, native CLI, native Skill and command in both arms. The direct arm used Docker and the upstream CLI explicitly. The AgentDock arm invoked the Builder's public build and run scripts, which also recorded package provenance. The direct Sand3D arm called the pinned upstream `docs/examples/bracket.py` function and exported its return value with `sand3d.export`. Its recipe used the same dependency layers as the AgentDock fixture. The AgentDock arm replayed the previously generated CLI and Skill at the frozen revision. No replay used Codex generation.

| Fixture | Workflow | Observed order within fixture | Build | Run and verify | Recorded sum | Verdict |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| E2E | Direct upstream CLI | 1 | 7.59 s | 12.94 + 0.05 s | 20.58 s | Pass |
| E2E | AgentDock fixture | 2 | 1.06 s | 11.48 s | 12.54 s | Pass |
| Sand3D | AgentDock fixture | 1 | 5.88 s | 1.64 s | 7.52 s | Pass |
| Sand3D | Direct upstream API | 2 | 6.68 s | 1.73 + 0.09 s | 8.50 s | Pass |

All four Docker builds, application containers and independent verifiers exited zero. The E2E reports each contained the expected successful `home lists the scenarios and opens one` case. All four verified Sand3D exports, including the two generated-pair checks, were byte-identical and contained 1,220 plate triangles, 80 × 40 × 6 mm extents and open hole centres at ±25 mm.

The AgentDock recorded sums were 8.04 s lower for E2E and 0.98 s lower for Sand3D in this sample. The clocks covered different packaging overhead. The direct build clock began after context staging, and the AgentDock build clock included source archiving and Sand3D wheel copying. AgentDock included manifest inspection in its run clock. The direct Sand3D build also had a final-layer cache miss. The first direct Sand3D attempt stopped in the host harness before Docker because macOS Bash treated an empty argument array as unbound. The one manual correction removed that empty expansion. The reported direct result is the subsequent run from the staged clean context. There were no other trial-specific corrections. These timings are observations of these invocations. The sample size, shared cache and different staging boundaries leave the underlying performance difference unresolved.

## Proof and reproduction

[Trial records](v0.1-measurement/trials.json) retain the source, verifier, evidence and image identities, phase timings, process exits and structured outcomes. The [compressed E2E reports](v0.1-measurement) retain the original bytes. The [positive GLB](v0.1-measurement/bracket.glb) is shared by the four byte-identical exports. Negative controls outside the clocks returned verifier exit 1 for an altered E2E expected title and for a [70 mm plate](v0.1-measurement/sand3d-negative.glb) emitted by the CLI with exit 0. The fresh prompts, generated recipes and generated Sand3D harnesses are stored with the records. Full Codex events, BuildKit logs and container logs were recorded locally under `/private/tmp/agentdock-ticket03`.

Replay AgentDock with the documented public commands from the frozen revision. For the E2E direct replay, use the same Dockerfile and build arguments as the fixture. Give it a fresh exact archive under `source/`, take the local ID from `docker build --iidfile`, then run the Dockerfile's upstream CLI command directly with the stated sandbox controls. Save stdout and invoke `python3 skills/agentdock-builder/scripts/verify-e2e-report.py report.json`. For direct Sand3D, use the [recorded Dockerfile](v0.1-measurement/sand3d-direct.Dockerfile), a new pinned archive under `source/`, and the pinned wheel under `wheel/`. In the container, prepend `/app/source/docs/examples` to Python's import path, call `sand3d.export(bracket(), "/tmp/bracket.glb")` using the upstream `bracket` function, and stream the file back to the host. Invoke `python3 skills/agentdock-builder/scripts/verify-sand3d-glb.py bracket.glb`. Both public verifiers are unchanged from the frozen revision.

## Matched follow-up

A second set of trials used the same fixture recipes and verifier code, with the evidence and direct Sand3D recipe frozen at `d5f61cb`. Each arm got the same pinned app source, platform, dependency pins, container controls, independent artifact expectations and a 360-second wall budget. The host and Docker version were unchanged.

### First use through verdict

The clock started when the outer runner submitted a fresh Codex request and stopped after independent verification. Codex CLI 0.156.1 used workspace-write mode, `gpt-6-sol` at medium reasoning, and a 300-second limit inside the 360-second total. The outer runner handled the approved Docker and verifier commands. Workspace and archive preparation and Docker approval occurred before the clocks. The sessions were separate and some overlapped on the same host and account.

For E2E, the upstream arm used the native CLI and Docker Skills to emit the exact CLI arguments for the common pinned Docker recipe. The AgentDock arm used its Builder Skill to identify the public build and run scripts, which the outer runner then invoked. Both ran the same smoke case. For Sand3D, both arms generated a fresh CLI and Skill with the pinned CLI-Anything workflow. The AgentDock arm received the Builder Skill as additional guidance and was explicitly asked to generate a new pair. Both Sand3D arms handed their generated files to the same frozen packaging recipe and verifier. This exercised first generation with Builder guidance supplied by the prompt. The released Builder Skill normally reuses the prepared pair.
